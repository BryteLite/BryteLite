WHISPERFORGE - The Build They Tried To Silence

Preface

After being a hacked by a bad actor, my prized rig was gone. My OS was org locked, my data was ascii souped and I had no control of my own services, even on a local account. I knew there was no way to recover what was lost on this machine. Instead of letting it die though, I chose a different path. I decided to wipe the drives clean and start new.

Step 1: Pick A Distro

There were a lot of distros to pick from. I've had some experience with Ubuntu and Arch, but neither really called to me as something I would use as a daily driver. In light of hardware that would soon go EOL and a standards baseline that was shifting, I knew I had a window (pun intended) to lock in a fresh baseline that can continue to use my hardware. Instead of shaming vendors for choosing the path of EOL for reference cards that still chug, I was going to take it upon myself to protect my rig when an organization had failed me. I selected a distribution that preserved the familiar workflow I had relied on.

OS Selection:

Linux Mint 22.1 “Xia” (MATE Edition)
Codename: xia
Base: Ubuntu 24.04 LTS “Noble Numbat"

I chose Linux Mint 22.1 "Xia" (MATE Edition), built on Ubuntu 24.04 LTS "Noble Numbat", to future-proof my hardware stack. With an AM4 platform and NVIDIA 2080 SUPER in play, I needed a distro that wouldn’t bottleneck performance or lag behind on driver support. The newer kernel and updated Mesa/NVIDIA stack in Noble allowed me to fully unlock GPU acceleration and audio throughput while leveraging PipeWire for high-fidelity audio. Despite the initial pain of firmware quirks and manual tuning, the long-term performance gains made it the right call over the more stable but aging Virginia release.

Step 2: Installing The Distro

The process was nothing new, find a Linux Mint ISO, get Rufus, install the bootloader and image to a USB stick and go. I was able to do this on a backup machine, but there were some gotchas (BIOS-level hurdles, service hangs, driver quirks). I had to target the most compatible Linux Mint ISO that I could speculate. I chose Xia, since it's built on Ubuntu that has good support for older hardware and is already mature. It sounded great on paper, but then getting the install working came with its own issues.

  1. My BIOS did not support UEFI on the Live USB OS. Secure Boot Off
  2. There are issues with firmware on mass-produced reference boards that seem biased towards Windows OS environments.
  3. Hours were spent reading the Kernel Debug Outputs figuring out what services were getting hung.
  4. I had to disable Realtek devices with snd_hda_intel=0
  5. It was determined that some services like Bluetooth would get hung up if pci=noaer was not added to kernel parameters.
  6. After getting through the services to boot, the Live USB ISO was used to install the OS to the disk.
  7. Once the OS was installed, the system was rebooted with the same kernel parameters as before.
  8. The microcode for the hardware was installed.
  9. Realtek was renabled and controlled through PipeWire.
  10. Some low level configuring was required to tinker with the audio pipeline in order to retain 192KHz sample rate.
  11. It was noted that modern browsers have access to the hardware directly through a dummy stub in Realtek usually reserved for "accessibility", this was removed. Now I get browser complaints. Oh well.
  12. Once the machine was stable, a backup was performed.

Step 3: Secure What Was Rebuilt

Part of this was my fault. I should have been maintaining my home rig. I was negligent to my rig being so busy with the 9-5, but that's not an excuse. Never again. Going forward I'd have my own backups. All disks will have encryption. TPM and runtime encryption is how I will operate. Process validation will become the norm. Nothing gets elevated processes, not even me. Root tty1? Dead. Remote Access? No one. Every time a process is performed, it will be audited. I'm taking back what's mine. Am I being paranoid? Not without just cause. If anything I am responding to the incident as a learning lesson.

Steps Taken:

  1. root tty1 access is no longer a thing. I manually authorize system configurations.
  2. Daily driver user account separated from the system configuration.
  3. ufw - Deny All
  4. Purge stale or not needed services.
  5. Automated Backup Services, timeshift, only available when user is authenticated with access keys encrypted at run time under three cryptographic hash sets.
  6. Utilize AIDE to track the integrity of system files.
  7. Audit Permissions For Every Service.
  8. When default installs add extra packages, I make my own tailored build.
  9. Troublesome Intel ME pipelines neutered, hardware restricted and/or monitored.
  10. BIOS is now locked.
  11. CSM disabled.
  12. Extra Boot Entries are removed.
  13. Pivoting to OS Development to ensure trusted runtime operation.
  14. VPN Traffic.
  15. Secure DNS.
  16. On the fly reconfigurations and Dead-Man-Switches.
  17. journalctl monitoring.
  18. bash script services to maintain system integrity.
  19. /etc/*/*.conf monitoring.

As the final move in reclaiming control, I will be reflashing the BIOS firmware after full OS stabilization. This eliminates any remaining low-level compromise, including potential UEFI rootkits or modified firmware partitions. The updated BIOS will have Secure Boot re-established with my own signed keys, CSM disabled, boot entries sanitized, and flash-write protection engaged. From the lowest layer up, this system is now mine—rebuilt, hardened, and silenced.

Step 4: Enjoy The Whisper

It's strange what kind of power you can get from your hardware when you cut out all the bloat. For a long time I've traded convenience for the monopolization of the platform I rightfully owned. Now the machine barely makes a sound. Under load it just prefers to "Whisper".
